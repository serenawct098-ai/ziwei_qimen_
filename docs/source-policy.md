# 來源政策

## 目的

本文件規定古籍原文、使用者鎖定裁定、官方日曆資料、工程標準與外部驗證來源在本系統中的角色。

它不建立第二套算法規則。

## 來源優先序

```text
使用者已確認的明確裁定
→ 《紫微×奇門傳統算法作業規格書》
→ 可追溯古籍原文、歌訣、定位表與格局表
→ 官方日曆與天文資料
→ 已確認的工程標準
→ 外部交叉驗證來源
```

若低優先序來源與高優先序來源矛盾，以高優先序來源為準。矛盾不得以 fallback、雙讀取、雙盤或平均值方式處理。

## 來源類型

| 類型 | `source_kind` | 可用範圍 |
|---|---|---|
| 古籍原文 | `classical_text` | 排盤、安星、格局、斷語的可追溯依據 |
| 歌訣 | `mnemonic` | 定位、順逆、安星與讀表依據 |
| 使用者鎖定裁定 | `locked_adjudication` | 派別選擇、晚子時、閏月、中五、五級、25 格等已明確定案內容 |
| 官方日曆資料 | `official_calendar_data` | 公農曆對照、官方年曆、公開天文資料 |
| 工程標準 | `engineering_standard` | 時區、星曆、資料版本、Schema、測試與部署邊界 |

## 原文保存規則

- `original_quote` 必須逐字保存。
- 原文只能在 `data/sources/` 保存一次。
- 機器表不可複製完整古籍段落；只使用 `source_refs`。
- 原文位置至少保存檔名、卷、章、段；資料足夠時可加行。
- 不可捏造原文、出處、卷章、頁碼或行號。
- 查不到原文而又未有使用者裁定的規則，不可進正式資料表。

## 使用者裁定規則

當規則不屬古籍逐字內容、但已由使用者明確裁定，來源條目必須使用：

```text
source_kind = locked_adjudication
verification_status = adopted_by_user
design_origin_note = 裁定原因或範圍
```

此標記只用於資料與工程內部追溯。客戶輸出時不得把裁定冒充古籍原文。

## 外部資料規則

香港天文台 1901–2100 公農曆資料可在完成授權、格式與來源核實後，作正式農曆轉換基準。

Overview 香港萬年曆只可作人工或自動化測試抽樣比對：

- 不可在 runtime 抓取。
- 不可作 fallback。
- 不可作第二份正式農曆資料表。
- 不可因結果差異而直接覆蓋主規格或正式資料。

Swiss Ephemeris、Astropy 等工具只可依 `docs/time-engineering-standard.md` 的責任使用，不能未經核實成為新的算法來源。

## 不可採用內容

以下不具正式算法效力：

- 舊 `effective_rules.md`。
- 舊 pipeline 文件。
- 舊系統架構文件內未被新主規格採納的治理或仲裁邏輯。
- 奇門五維加權公式。
- 未標明來源的網頁文案、社交媒體內容、論壇討論與模型記憶。
- 無法確認全量內容的資料表或片段。
